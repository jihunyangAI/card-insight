# memory_policy.md — 메모리 정책 (memory/card/)

## 저장하는 것
| 파일 | 내용 | 쓰는 시점 |
|---|---|---|
| `issuer_signatures.json` | 헤더 시그니처(상단 제목 행의 해시 + 컬럼명) → 카드사. 제목 행 원문은 이름이 있을 수 있어 저장하지 않는다. 사용자가 확인해 준 것만 저장 | `--issuer`로 재실행해 식별에 성공했을 때 |
| `monthly_summary.json` | 월별 집계: 총액, 건수, 커버 일수, 카테고리별 합계 | 리포트 생성에 성공한 뒤 |
| `card-issuer-map.md` | 사람이 읽는 식별 기록 (참고용) | 수동 |

## 저장하지 않는 것
- 개별 거래 (가맹점명, 거래별 금액, 승인 시각)
- 이름·카드번호·전화번호 등 PII. 마스킹된 값이라도 저장하지 않는다.
- 원본 파일 경로 이외의 파일 내용

이유: 메모리는 다음 분석의 **비교 기준**과 **카드사 자동 식별**에만 필요하다. 그 이상 저장하면 유출 시 피해만 커진다.

## 사용 규칙
- 비교 기준을 계산할 때는 입력 데이터에서 나온 월 요약이 메모리보다 우선한다. 메모리는 입력 폴더에 없는 과거 월만 보충한다.
- `monthly_summary.json`은 최근 12개월만 유지한다. 오래된 월부터 삭제한다.
- 쓰기는 임시 파일에 쓴 뒤 교체(atomic replace)한다. 실패하면 retry_policy.md를 따른다.
- 사용자가 카드사 매핑을 정정하면 해당 시그니처 항목을 덮어쓴다.

### 카드분석 메모리
위 "저장하는 것 / 저장하지 않는 것"과 겹치는 부분은 위 항목을 따른다. 메모리 용도는 **전월 비교 기준**과 **카드사 자동 식별** 두 가지로 한정한다.

- `memory/card/monthly_summary.json`: 월별 카테고리 합계, 총액, 건수, 커버 일수. 비교 기준은 전월만 쓴다 (architecture.md).
- 새 가맹점이 나오면 로컬 키워드 규칙으로 분류한다. 규칙에 맞지 않으면 "기타"로 두고, 리포트에 "미분류 가맹점" 목록으로 표시한다 (retry_policy.md "카드분석검증").
  - 분류 결과는 메모리에 저장하지 않는다.
  - 어떤 경우에도 1/2/3 선택 메뉴로 사용자에게 묻지 않는다 (블로킹 질문 금지). 카드사 식별 실패 시의 확인 질문은 이 규칙과 별개다.

검토 후 제외한 항목:
| 항목 | 제외 이유 |
|---|---|
| `long_term/merchant_category_map.json` (가맹점→카테고리 매핑사전) | 가맹점명 저장 금지. 신뢰도가 키워드 일치 1.0 / 불일치 0이라 0.9 기준으로 저장해도 얻는 정보가 없음 |
| `working/this_month_anonymized.json` (이번 달 익명화 거래 캐시) | 개별 거래 저장 금지 (마스킹·익명화된 값 포함). 요청 시에만 실행되므로 7일 자동삭제를 수행할 주체가 없음 |
| `long_term/` 하위 경로, 전분기 비교 | 월별 요약 위치는 `memory/card/` 유지. 비교 기준은 전월로 통일함 |
