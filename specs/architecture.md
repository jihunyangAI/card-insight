# architecture.md — 카드사용내역분석 에이전트 구조

## 흐름
```
요청(자연어) ─▶ main.py
                 │ 1. main.parse_request : 요청에서 분석 월•요청 종류•강조 토픽 추출 (월이 없으면 데이터의 최신 월)
                 │ 2. csv_loader        : 입력 폴더 탐색 → 헤더 인식 → 카드사/월 식별 → 거래 정제 (merchant_normalizer로 PII 마스킹)
                 │ 3. category_classifier → statistics_engine → advisor : 분류 → 평균소비 / 주 사용처 / 과소비 Top3 → 절약제안•검증
                 │ 4. report_writer     : output/card-report/{YYYYMMDD}_report.docx 생성
                 │ 5. statistics_engine : 월별 집계 요약만 memory/card/에 저장
                 ▼
          표준출력: 결과파일 경로 + 핵심 3줄 + 면책문구
```
모든 단계는 로컬에서만 실행한다. 외부 API·LLM 호출은 하지 않는다 (guardrails.md).

## 입출력
- 입력: `../harness-book-samples/card-insight/*.xlsx|*.csv` (`--input`으로 변경 가능, `~$` 임시파일 제외)
- 출력: `output/card-report/{YYYYMMDD}_report.docx`
  - `YYYYMMDD` = 분석 월의 말일 (예: 2026-05 → `20260531_report.docx`). 같은 월을 다시 분석하면 덮어쓴다.

## 데이터 정제 규칙
- 헤더 행: 상단 15행 안에서 `날짜·가맹점·금액` 컬럼이 모두 있는 첫 행.
- 날짜가 해석되지 않는 행(소계·합계 행, 첫 열 `-`)은 제외.
- `승인구분`이 `취소` 또는 `취소전표접수`인 행은 원거래와 취소가 한 쌍이므로 둘 다 제외.
- 여러 파일에 같은 거래가 있으면 (날짜, 시각, 가맹점, 금액, 승인구분)으로 중복 제거.
- 분석 월 = 승인일이 그 달에 속하는 거래만. 파일 이름이나 파일 단위로 묶지 않는다.
- 할부 거래는 승인 시점에 전액 계상한다 (청구 기준 아님).

## 지표 정의
- 커버 일수 = 분석 월 안에서 첫 승인일 ~ 마지막 승인일 (일부 기간만 담긴 파일 보정용).
- 일평균 = 총액 / 커버 일수, 주평균 = 일평균 × 7, 건당 평균 = 총액 / 건수.
- 비교 기준(전월) = 분석 월의 직전 달. 입력 데이터에 없으면 메모리의 월별 요약을 쓴다.
  - 두 달의 커버 일수가 다를 수 있으므로 카테고리별 일평균으로 환산해 비교한다.
  - 전월 지출이 0인 카테고리는 증가율 대신 "전월 없음(신규)"으로 표시한다.
  - 전월 데이터가 없거나 커버 일수가 7일 미만이면 비교하지 않는다. "전월 데이터 없음"으로 표시하고, 과소비 Top3 대신 이번 달 금액 상위 3개 카테고리를 보여준다.
- 과소비 Top3 = 전월보다 높은 카테고리 중 초과액이 큰 순서 (증가율 순이 아님). 금액이 3만원 미만이거나 총액의 3% 미만인 카테고리는 제외한다.
  - 초과액 = (이번 달 일평균 − 전월 일평균) × 커버 일수. 한 달로 외삽하지 않는다.
- 커버 일수가 해당 월의 80% 미만이면 리포트와 출력에 "N일 중 M일치만" 경고를 표시한다.

## 표준출력 규칙
main.py의 표준출력은 Claude Code가 읽어서 답변에 쓰므로 외부 API 전송으로 본다 (guardrails.md 3번). 금액은 docx 리포트에만 담는다.
- 출력하는 것: 결과파일 경로, 분석 월(YYYY-MM), 카테고리명, 비율(전월 대비 X%, 총액 대비 비중 X%), 건수, 커버 일수 경고("N일 중 M일치만"), 면책문구, 종료코드별 안내.
- 출력하지 않는 것: 금액(총액, 카테고리 합계, 초과액, 절감액 모두), 가맹점명, 거래 날짜•시각, PII.
- 핵심 3줄 형식:
  1. 총 사용액: `총 사용액: 전월 대비 X% 증가 (금액은 리포트 참조)`. 전월 데이터가 없으면 `총 사용액: 리포트 참조 (전월 데이터 없음)`.
  2. 과소비 Top3: `과소비 Top3 (전월 대비, 초과액 순): 카페(전월 대비 X% 증가), ...`. 전월 지출이 0이면 `전월 없음(신규)`. 전월 데이터가 없으면 `금액 상위 3개: 쇼핑(비중 X%), ...`.
  3. 절약제안 요약: `절약제안: 카페•쇼핑 카테고리 검토 권장 (절감액(추정)은 리포트 참조)`.
- 종료코드 3의 헤더 출력은 컬럼명만 PII 마스킹 후 출력한다. 제목 행은 라벨 없는 이름이 있을 수 있으므로 줄 수만 표시한다. 디버그 출력은 건수만 출력한다.

### 카드분석 기술아키텍처
위 항목과 겹치는 부분은 위 항목과 CLAUDE.md 핵심원칙을 따른다. 아래는 위 항목에 더하는 내용이다.

#### 0. 자연어 라우팅 (main.py의 parse_request)
- 입력: 사용자 자연어 한 문장. 보조 옵션은 `--issuer`(카드사 확인 후 재실행), `--input`(입력 폴더 변경) 두 가지만 둔다.
- 추출 항목:
  - 대상 월: "4월"·"이번달"·"지난달". 지정이 없으면 입력 데이터의 가장 최근 월.
  - 요청 종류: 리포트 / 전월비교 / 디버그 / 단정표현거부
  - 강조 토픽: 특정 카테고리("카페"·"외식" 등)를 언급하면 리포트 맨 앞(요약 위)에 그 카테고리의 요약 단락을 넣는다. 내용은 금액, 비중, 전월 대비 %, 과소비 Top3 포함 여부다. 카테고리명은 키워드 규칙 표의 카테고리로 맞춘다 (예: "외식" → 식비). 맞는 카테고리가 없으면 강조 없이 리포트를 만든다.
- 라우팅 결과를 dict로 반환한 뒤 해당 모듈을 호출한다.
- 요청 종류별 동작:
  - 리포트·전월비교: 같은 리포트를 만든다. 리포트에는 전월 비교가 항상 들어간다.
  - 디버그: 리포트 대신 파일별 헤더 행 위치, 식별된 카드사, 월별 건수, 제외한 행 수를 출력한다. 가맹점명은 출력하지 않는다.
  - 단정표현거부: "끊어"•"단호하게"•"강하게" 같은 어조 단어가 있으면 리포트를 만들지 않고 거부 메시지(guardrails.md "거부 메시지 형식")를 출력한 뒤 종료코드 1로 끝낸다.

#### 1. 데이터 소스
- 입력은 로컬 csv/excel만 쓴다 (harness-book-samples/card-insight/).
- 외부 데이터 호출 금지 (카드사 API•은행 오픈뱅킹 등 모두 차단).
- LLM을 호출하지 않는다. 나중에 추가하면 가맹점명•금액•날짜를 모두 익명화 토큰으로 치환한 뒤에만 보낸다 (guardrails.md 3번). 반올림한 금액도 보내지 않는다.

#### 2. 파싱•정규화 (csv_loader.py + merchant_normalizer.py)
- 카드사별 헤더 어댑터: 신한카드 확인됨 (memory/card/card-issuer-map.md). 삼성•현대 등은 사용자가 확인해 준 시그니처로 추가한다.
- 식별 실패 시 헤더를 출력하고 종료코드 3. 확인된 시그니처는 `memory/card/issuer_signatures.json`에 저장한다 (memory_policy.md).
- 헤더 탐색 범위는 상단 15행이다 (위 "데이터 정제 규칙").
- 매칭에 실패해도 LLM으로 보조하지 않는다.

#### 3. 카테고리 분류 (category_classifier.py)
- 사전정의 카테고리: 식비/카페/교통/쇼핑/의료/여가/구독/생활비/기타 (확장 가능)
- 로컬 키워드 규칙으로만 분류한다. 신뢰도 0.6 미만은 "기타"로 두고 리포트에 "미분류 가맹점" 목록을 표시한다 (retry_policy.md "카드분석검증").
- 실행 중 사용자에게 되묻지 않는다.

매칭 방법:
- 가맹점명 전체(결제대행 표기 `KCP_결제 - (주)OO`, `이니시스 - (주)OO`처럼 " - " 뒤 법인명 포함)에서 공백을 지우고 대소문자를 무시한 뒤, 키워드가 포함되어 있으면 일치로 본다.
- 영문 2자 키워드(`KT`, `CU`)는 앞뒤가 영문자가 아닐 때만 일치로 본다 (예: `KT통신요금` 일치, `KTX`•`CUBE` 불일치).
- 여러 키워드가 맞으면 가장 긴 키워드를 따른다 (예: "쿠팡이츠"는 "쿠팡"보다 길어서 식비, "노브랜드버거"는 "노브랜드"보다 길어서 식비). 길이가 같으면 표의 위쪽 카테고리를 따른다.
- 키워드는 일반 상호•업종명이며 사용자 거래 데이터가 아니다. 코드에서는 analyzer.py의 한 곳에만 정의한다.
- 규칙을 넓히려면 이 표에 키워드를 추가한다. 실행 중 학습하거나 메모리에 저장하지 않는다 (memory_policy.md).

#### 4. 통계 계산 (statistics_engine.py — 파이썬만)
- 카테고리별 합계, 건당 평균, 건당 금액 표준편차.
- 전월 대비 증가율: 위 "지표 정의"를 따른다 (입력 데이터 우선, 없으면 `memory/card/monthly_summary.json`).
- 자기평균 대비 z-score: 메모리 월별 요약이 3개월 이상 쌓이면 카테고리별 일평균으로 계산해 카테고리 표에 참고값으로 표시한다.
- 과소비 Top3 선정 기준: 위 "지표 정의"를 따른다 (전월 대비, 초과액 순, 3만원•총액 3% 미만 제외).
- 절대 LLM에게 산수를 맡기지 않는다.

#### 5. 절약 제안 생성 (advisor.py)
- 파이썬 계산 결과로 로컬 문장 템플릿에서 만든다. LLM을 쓰지 않는다.
- 출력 검증: 각 제안에 정량근거(금액 + 전월 대비 %)가 있어야 한다 (retry_policy.md "카드분석검증").
- 단정 표현이 발견되면 바꿔 쓰지 않고 리포트를 만들지 않은 채 중단한다 (guardrails.md 4번).

#### 6. 출력 (report_writer.py)
- `output/card-report/{YYYYMMDD}_report.docx` (위 "입출력")
- python-docx로 만들며 구조는 다음과 같다.
  1. 요약: 총 사용액 / 일평균•주평균•건당 평균 / 전월 대비. 커버 일수 경고가 있으면 함께 표시
  2. 카테고리별 표: 금액 / 비중 / 전월 대비 (z-score는 3개월 이상일 때만)
  3. 주 사용처 Top5: 금액 상위 5개 가맹점 (마스킹된 이름)
  4. 과소비 Top3: 선정 기준 문구 "전월 대비, 초과액 순"과 정량근거 포함
  5. 절약 가능 영역: 영역별 절감액 "(추정)". 초과액 기준이며 한 달로 외삽하지 않는다
  6. 참고: 미분류 가맹점 목록, 단일 가맹점 월 100만원 이상 표시 (guardrails.md)
  7. 면책문구: 마지막 단락 (guardrails.md 5번)

#### 7. 의존성
- openpyxl, python-docx (이미 설치되어 있음). pandas•anthropic은 쓰지 않는다.

#### 8. 자체검증 체크리스트 (개발 단계에서 수행)
1. `pip list`에 openpyxl, python-docx가 있다.
2. `main.py "4월지출 정리해줘"` 실행 시 `output/card-report/20260430_report.docx`가 생성된다.
3. 생성된 docx의 마지막 단락에 면책문구가 있고, 카테고리 합계 = 총 사용액 (±0.1%).
4. 외부 네트워크•LLM 호출이 없다. 나중에 호출을 추가하면 로그에 익명화 토큰만 보여야 한다.
5. `main.py "카페 끊으라고 강하게 말해줘"` 실행 시 단정 표현 거부 메시지가 나온다.
- 하나라도 실패하면 원인을 고친 뒤 다시 검사하고, 모두 통과해야 다음 단계로 진행한다. 코드 작성•수정은 사용자 확인을 받은 뒤 한다.
